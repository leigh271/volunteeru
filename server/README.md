# Authenticated VolunteerU foundation

Run with Node 22 or later:

```sh
npm run server
npm run dev
npm run test:server
```

The API listens on `127.0.0.1:3001`. Vite proxies `/api`; use the **Integrations** page for authenticated records. Browser demo records are deliberately not imported into server accounts. Copy settings from `server.env.example` into your shell environment; the app does not automatically load this file.

SQLite persists to `server/data/volunteeru.sqlite` unless `DATABASE_PATH` is set. Its directory is mode 0700 and database mode 0600. The database stores personal records and hashed credentials; keep it out of source control, back it up securely, and use an encrypted disk where required. SQLite is an experimental built-in Node feature in Node 22.

Registration accepts `school_admin`, `nonprofit`, or `student`. Coordinator registration creates a new isolated school or organization and records an authorization declaration; the prototype does not verify real institutional authority. Students require an age of 13+ and an unexpired school invitation. Invitation tokens are random, stored only as SHA-256 hashes, expire in seven days, and default to 100 uses (configurable 1–1000). Registering consumes one use atomically and links the student to that school.

Passwords use salted scrypt. Sessions use a random HttpOnly SameSite=Strict cookie, store only its hash, and expire after 12 hours. Sign-in and registration have in-memory rate limits; production deployments need a shared rate limiter, account recovery, verified institutional onboarding, HTTPS, monitoring, backup/restore, and appropriate consent workflows. Set `PUBLIC_ORIGIN` to the exact HTTPS frontend origin and `SECURE_COOKIE=true` in production behind an HTTPS reverse proxy. CORS is not enabled.

Every authenticated mutation requires the `X-CSRF-Token` returned by register/login/session. Mutations require JSON objects, reject cross-origin requests, and cap request bodies at 32 KB. Sessions and CSRF tokens belong to the authenticated workspace; the demo API configuration cannot grant access.

## API contract

All routes use `/api`. Errors are `{error}` and contain no SQL or credential details.

| Method and route                                  | Payload / response                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /health`                                     | API mode; no account data.                                                                                                                                                                                                                                                                                                             |
| `POST /auth/register`                             | `{role,name,email,password,authorized?,schoolName?,requiredHours?,organizationName?,age?,invitationToken?}` → `{user,csrfToken}` plus cookie. Password 12–128 characters. Coordinators require `authorized:true`; students require an invitation and age.                                                                              |
| `POST /auth/login`                                | `{email,password}` → `{user,csrfToken}` plus cookie.                                                                                                                                                                                                                                                                                   |
| `GET /auth/session`                               | Current `{user,csrfToken}`; never password hashes.                                                                                                                                                                                                                                                                                     |
| `POST /auth/logout`                               | `{}`; revokes current session.                                                                                                                                                                                                                                                                                                         |
| `POST /schools/invitations`                       | School admin only, `{maxUses?}` → token, registration link, expiry.                                                                                                                                                                                                                                                                    |
| `GET /events`                                     | Own organization events for nonprofits; published events for other signed-in roles.                                                                                                                                                                                                                                                    |
| `POST /events`                                    | Nonprofit only: `{title,date,startsAt,hours,location,city,minAge,volunteerTarget,description,requirements,status,lat?,lon?}`. `startsAt` is an ISO timestamp with an explicit UTC marker or offset and must match the declared event date in America/New_York; `location` is Broward, Miami-Dade, or Remote; `status` draft/published. |
| `PATCH /events/:id`                               | Own nonprofit event fields; approved registrations block schedule changes and prevent lowering target below approved count.                                                                                                                                                                                                            |
| `GET /applications`                               | Own student applications or own nonprofit event registrations.                                                                                                                                                                                                                                                                         |
| `POST /applications`                              | Student only `{eventId}`. Server derives student, checks age, publication, future schedule, and uniqueness.                                                                                                                                                                                                                            |
| `PATCH /applications/:id`                         | Own nonprofit event `{status:'approved'                                                                                                                                                                                                                                                                                                | 'rejected'}`. Approval rechecks age, publication, future schedule, and target. Verified participation cannot be declined. |
| `GET /attendance`                                 | Own student or own nonprofit-event attendance records.                                                                                                                                                                                                                                                                                 |
| `POST /attendance/check-in`                       | Student `{applicationId}`; requires approved registration, event window from 30 minutes before start until end, and no previous check-in.                                                                                                                                                                                              |
| `POST /attendance/check-out`                      | Student `{applicationId}`; measures authoritative server time, clamps to event schedule and duration, and creates one pending hours record atomically. Client hours input is ignored.                                                                                                                                                  |
| `PATCH /attendance/:id`                           | Nonprofit `{status:'present'}` after the event ends and checked-out attendance exists.                                                                                                                                                                                                                                                 |
| `GET /hours`                                      | Scoped student/nonprofit hours.                                                                                                                                                                                                                                                                                                        |
| `POST /hours`                                     | Student `{applicationId}` returns existing timed record; no arbitrary manual hours are accepted.                                                                                                                                                                                                                                       |
| `PATCH /hours/:id`                                | Nonprofit `{status:'approved'                                                                                                                                                                                                                                                                                                          | 'needs_corrections',correctionNote?}`. Approval requires completed approved attendance, event end, and no time inflation. |
| `GET /reports/school`                             | Admin’s own school and connected students’ approved hour totals only.                                                                                                                                                                                                                                                                  |
| `POST /notifications`                             | Nonprofit `{eventId,message}` queues in-app updates for that event’s pending/approved applicants. No email or SMS delivery.                                                                                                                                                                                                            |
| `GET /notifications`                              | Signed-in student’s in-app outbox entries.                                                                                                                                                                                                                                                                                             |
| `POST /nonprofit/plans`                           | Nonprofit `{transcript}`. Organization comes from session; optional body organization ID must match. Explicitly sends notes to the configured server AI provider. Returns 503 when unconfigured.                                                                                                                                       |
| `POST /nonprofit/reports`                         | Nonprofit `{month?,eventId?}`. Optional month uses YYYY-MM and optional event must belong to that month and organization. Server derives organization-scoped event records and approved hour aggregate; ignores caller-supplied reports. Optional AI provider creates a draft with scoped evidence IDs.                                |
| `GET /maps/nearby?lat=26.12&lon=-80.14&radius=25` | Authenticated search of published stored event coordinates, using straight-line distance. South Florida coordinates and radius up to 200 km. No geocoding or location permission.                                                                                                                                                      |

`server/providers.js` contains the optional AI provider interface. Secrets are server environment variables; no credentials are exposed in frontend files. Meeting AI evidence must be an exact source substring. Impact summaries must cite supplied scoped record IDs. Outputs remain reviewable drafts; no event or report is automatically published. The API uses prepared SQL statements and explicit role and ownership checks; browser storage is never an authorization boundary.
