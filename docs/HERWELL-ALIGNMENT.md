# HerWell hackathon alignment

Source repository: https://github.com/leigh271/volunteeru (main at clone time; exact base in Git history).
The former `../volunteer-platform` Python directory is retained as an earlier prototype. The integrated demo is now in this repository, using its existing Vite/JavaScript stack and existing student/school/nonprofit stores.

## Demo walkthrough

1. Run the app, open `/?view=nonprofit&demo=herwell`, and choose **Load HerWell mock data** once.
2. The Demo Tour opens the existing student and school experiences using imported fictional records.
3. Open **Command Center**: choose E001 or E002, inspect staffing/training, logistics, and source-linked preparation tasks. Optional food/decorations stay unassigned and undated until review.
4. Open **Event day** to inspect attendance and enter anonymous demo operational concerns. This does not dispatch notifications; the visible urgent queue is local to the coordinator.
5. Open **Follow-up** to review missing checkouts or complete time pairs. A correction requires actual time and a reason. Approved hour totals change after review; the original fixture starts at 81.76.
6. Use **Volunteer Directory** to combine name/school search with school, education, event county, interest, skill, available day, age group, event, and registration-date filters. Export filtered CSV.
7. Use **School Reports** to compare schools, approved hours, recruitment, and campaign sources. Registration-period filters are explicit; they are not attendance-period filters. Original **Impact Reports** offers its existing event/month filtering over the bridged records.
8. The existing school chart uses a clearly labeled December 18, 2026 as-of date only for this tagged future-data fixture. Other schools retain real current-date behavior.

## Fixture validation

Initial: 100 students, 112 submissions, 12 repeats, 10 schools, 150 recruitment target, 100 planned shift places, 35 attendees, 65 no-shows, 3 missing checkouts, 2 complete pending reviews, 81.76 approved hours. Education: 40 high school, 44 undergraduate, 16 graduate. The provided guide mentions repeated full names, but the actual supplied 100 full names are distinct; deduplication still uses normalized emails and stable IDs.

Original source files are retained in `public/herwell-demo`. `scripts/import-herwell.py` rebuilds `dataset.json` and validates actual-time calculations. It can take a new ZIP path; it reads only the known file names and never executes source text. Run `npm run test:demo` for adapter checks and `npm run test:server` for existing auth/backend regression checks.

## Remaining production work

This is a coherent hackathon demo, not a claim that all three roadmap phases are deployed. Production needs the existing API connected to the new coordinator screens, reviewed guardian-consent and organization membership flows, school authority verification, retention/backups, external delivery providers, and configured AI credentials. No hosted deployment or external service connection was created. Native AI/provider calls remain unconfigured unless the existing backend is configured separately. Direct PDF download, full school invitation-token import into server accounts, and cross-device synchronization are not added here. CSV exports are functional and protect formula-like cells. School Reports also provides browser print / Save as PDF. The student growth visual now follows the connected school’s hour requirement; unlinked students retain the 40-hour personal milestone fallback.

## Command center design revision

The coordinator command center now follows five compact steps: **Prepare → Invite → Review volunteers → Check in → Check out**. Before-event and event-day phases have larger top tabs. Tasks, outreach channels, volunteer groups, and attendance groups are collapsed by default, with short expandable lists rather than a full ledger. A persistent bottom progress bar offers Back and Next; browsing a stage does not mark it complete.

HerWell Community Alliance remains the example organization. Preparation contains only relevant tasks and the volunteer staffing need. Historical attendance and approved-hour totals no longer crowd this screen. Invitations have entries for LinkedIn, Eventbrite, Blueboard, email, and text; saved URLs and coordinator-recorded external sharing do not claim an API connection or delivery.

Coordinator event-day roster approval is separate from the fixture’s source registration confirmation. New approvals require completed source training and recorded guardian consent for minors. Finalizing a team below the staffing target requires a coordinator note. A changed roster decision invalidates prior finalization. Existing source registrations and approved-hour records remain intact.

The outreach assistant currently previews editable templates; the registration assistant performs deterministic duplicate and count checks. They do not call a live AI model or use OpenAI credits. Automatic nonresponse detection cannot run because delivery/reply data and external providers are not connected. Reminder, not-selected thank-you, and missing-checkout messages are drafts only. Check-in includes an approved-demo-student preview link; it is not a new live identity or QR attendance system. The existing authenticated Integrations attendance system is preserved. Follow-up reporting beyond check-out remains outside this design revision.
